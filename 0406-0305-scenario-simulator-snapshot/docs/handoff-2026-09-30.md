## Mart: content vs code (Ask-mode breakdown, full)

Here’s the Mart split, by topic.

### Images / visual assets
**From content:** scene image(s), travel images, door fallback, phone fallback, per-option icons (`assets.*`, `options[].icon`). Scenes are picked by `decision.order` (`sceneImages[(order-1) % n]`). Travel images use `(order-2) % n` between decisions.

**Fixed in code:** How those URLs are used (full-bleed scene, hotspot overlay, travel overlay, car animation, option icon sizes). Hotspot is a rectangle only — no image crop from content. Fallback if an option icon 404s: `call` → phone image, else door image.

**To make more content-driven:** Easy for extra image slots/labels. Medium if you want per-decision layout modes or non-rectangle hotspots.

---

### Number of decisions
**From content:** `decisions[]` length (schema: ≥1). Current exercise has 6. Progress UI and scoring use `game.decisions.length`.

**Fixed in code:** Flow is always intro → one decision at a time → reveal. Exactly **3 options per decision** (schema `.length(3)`). Option ids must be `"A" | "B" | "call"`.

**To loosen:** Medium — drop the fixed 3 and the `A/B/call` enum; UI is already a map over options, but icon fallback and some facilitator assumptions treat `call` specially.

---

### Days / week structure
**From content (copy only):** Intro/playbook/reveal strings talk about “week”, “day”, “month” (e.g. playbook rule “Every call takes a day”). Scoring UI strings like `thisWeek` / `weekSlow`.

**Fixed in code:** There is **no calendar or day counter**. “Week” is narrative, not a state machine. Buttons say “Start the week” / “Next branch” / “Branch N of M” in code. Timer is workshop duration (default 15 min for branching), not days.

**To make content-driven:** Easy for button labels. Hard for a real day/week mechanic (new state, when “day” advances, how call cost works).

---

### Locations / branches & movement
**From content:** Each decision has `location.name` (today: `{{chain.name}}, {{branches.*}}`). Player moves by advancing `decisionIndex`; travel overlay shows “On the road to {place}” using the **substring after the last comma** of that name (`placeName`).

**Fixed in code:** Sequential path only (no map, no choosing order, no revisiting). Travel animation timings are hardcoded. Branch rename variables (`branches.alNahda`, etc.) are in the **variable schema / seed**, not a first-class “locations” list in the engine.

**To make content-driven:** Easy for more/fewer sequential stops (add decisions + matching scene/travel images). Medium for free navigation or a real map. Easy to put travel chrome strings in content.

---

### Role & manager wording in the UI
**From content:** `intro.role`, `intro.setting`, `intro.goal`, playbook title/rules, option labels/immediate text (often “area manager”), deferred headlines, scoring style copy.

**Fixed in code:** Reveal step 2 chrome: “Your decisions and your manager's review of them” and “This is your manager's read, based on the company's field playbook.” Also “Start the week”, “Next branch”, “See what happened”, “Question N · …”, “You chose”, “Discuss”, “Rule N”, “When you are ready, return to the main workshop room”.

**To make content-driven:** Easy — lift those strings into `reveal` / `scoring.ui` / a small `chrome` block.

---

### Escalate option
**From content:** The third option’s **label and consequences** (usually “Call your area manager”). Grades/tags/rationale for that choice.

**Fixed in code:** Third slot **must** be id `"call"`. UI treats `call` differently (smaller icon height; phone image fallback). Pedagogy that “call costs a day” lives in playbook/copy and grades (`tooSlow`), not as an engine rule that advances a day counter.

**To make content-driven:** Medium — allow arbitrary option ids and a flag like `kind: "escalate"` for icon/fallback, instead of hardcoding `"call"`.

---

### Door types
**From content:** `options[].facilitator.doorType` (strings today: `two-way`, `one-way`, `murky`, `n/a`) and decision-level `facilitator.difficulty` / `note`. Shown on the **facilitator** board.

**Fixed in code:** Player never sees door type. Facilitator highlights `difficulty === "murky"` with a special background. Door type is free text in schema — not an enum — but teaching meaning is only in notes/copy.

**To make content-driven:** Already mostly content. Easy to show door labels to players or style by a small allowed set. Medium if door type should drive scoring automatically (today scoring uses `grade` / `tag`, not door type).

---

### Scoring
**From content:** Grade labels/points, `maxPointsPerDecision`, tag names/templates (`{branches}`), style thresholds (`operatorMaxLost`, `bottleneckMinLostEach`), 2×2 axis labels, four style personas (keys must be `operator` / `escalator` / `cowboy` / `bottleneck`), most reveal style UI strings.

**Fixed in code:** The **algorithm** in `decision-engine.ts`: sum points; accumulate “lost” by `tooSlow` / `tooFast`; then pick style with fixed if/else order (operator → bottleneck → escalator vs cowboy). Exactly two tags. Exactly four named styles. Grade keys are a fixed enum (`best`…`worst`). “Branch N” phrasing in tag lines is coded.

**To make content-driven:** Medium for thresholds/copy (already largely there). Hard for a different style model (e.g. 3 axes, no escalate/cowboy metaphor) without rewriting the scorer and `StyleGrid`.

---

### Reveal
**From content:** `reveal.title` / `masthead` / `dateline`; each option’s `deferred` story (headline, standfirst, weight, outcome); per-decision breakdown fields (grade, tag, rules, rationale); style block copy via `scoring`.

**Fixed in code:** Three-step reveal UI (newspaper → manager review → style grid). Stories sorted by `weight` descending; lead + two-column rest. Newspaper/print animation. Hardcoded manager framing (above). Closing “return to the main workshop room”. Grade colors in code.

**To make content-driven:** Easy for manager/closing strings and maybe step titles. Medium for alternate reveal layouts (e.g. no newspaper, different step count).

| Week/days | Narrative copy only | No day system; “week” button labels | Easy (copy) / hard (real days) |

| Role/manager | Intro + most story copy | Several reveal/chrome strings | Easy |
| Escalate | Copy + grades | Must be option id `call` | Medium |
| Door types | Facilitator metadata | Player ignores; murky highlight | Mostly done |
| Scoring | Points, tags, styles, most UI | Fixed algorithm + 4 style keys | Medium–hard |
| Reveal | Stories + titles + style text | 3-step layout + manager chrome | Easy–medium |
